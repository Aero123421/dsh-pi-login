# 0.7.3

接続・認証情報・モデル一覧の保存と、途中失敗からの復旧を見直しました。対応DSH版は引き続き `0.2.1-alpha.2` です。

## 接続と認証情報

- 接続削除の途中でCredentialsの削除が失敗しても、オフの「削除未完了」行を残します。再起動後もSettingsからDeleteを再試行できます。専用の認証情報と回収候補を削除してから、行を消します。
- APIキーで新規接続を作る時は、先にオフの接続を保存します。認証保存や有効化が失敗した場合は作成済みの接続から復旧を案内し、同じフォームの再Addで重複を作りません。
- キー交換・認証方式変更の途中で取り残されたrecordを、接続内の回収候補として保存します。「認証情報の削除を再試行」で、現在のキーを維持したまま回収できます。新しいキーへの交換後に古いキーの回収だけ失敗した場合も、未完了を表示します。
- 未ロードのoptional integrationが残っていても、無関係な接続を編集・削除できます。別の接続が使用中の認証情報は回収しません。

0.7.2以前の失敗で既に孤立した認証recordは、所有者を推測して一括削除しません。削除・認証情報回収が未完了の間は、0.7.3で処理を完了してから別の版へ変更してください。

## Muse一覧と画面操作

- Muse再認証の開始時に、認証世代の更新と古い保存一覧の削除を同時保存します。別アカウントの一覧が取得失敗後に残る問題を防ぎます。再認証を取消した場合も一覧の再取得が必要ですが、以前の認証情報と明示的なモデル選択は保持します。通常の同アカウントの再起動・キー更新では保存一覧を利用できます。
- 通常版とContributor版の両方を取得し、保存が成功してから一覧へ反映します。一部取得・保存失敗を成功扱いにしてモデルを消したり、再起動後に無言で元へ戻したりしません。使用量・プランと発行キーもアカウント変更・取消・解除を照合します。
- 古い画面や保存キューから、新しいプロフィール・認証世代へ書き込みません。別操作で変更された設定を古いフォームから上書きする場合も、競合として表示します。
- サービス切替時に隠れたendpoint/API入力を引き継ぎません。通信方式には「プロバイダーの既定値」を表示し、既存のoverrideを解除できます。

## 探索・更新・配布

- 保存済みのキーとヘッダーを、異なるdraft endpoint/APIのモデル探索へ引き継ぎません。明示的なdraft用キーは元のヘッダーを継承せず、redirectは拒否します。
- 標準managerやCLIで新版を導入した場合も、導入版と実行版の差を「再起動待ち」として表示します。
- 更新tgzの全entry・path・種類・header checksum・終端を検査します。リンクや未対応のpath変更拡張を拒否します。
- SDKが後から補完したツール名・IDをstream表示へ反映します。
- Clientに含まれるclsxのMIT通知を配布ファイルへ追加しました。手動Releaseでも公開tagのRelease notesを使用します。

## 検証

保存・認証・通信の途中失敗、世代交代、再起動、同時操作、他接続の保持を回帰テストで確認します。実Pi SDK、公式Hostサービスと認証済みRPCを使うChromium画面操作、実DSHへのtgz導入・本物のSettings画面、公開tagと配布ファイルの照合を組み合わせます。

使用する認証と応答はテスト用です。実アカウントのMuse生成・利用枠・課金、各OS実機は未検証です。設計の責任分担と復旧手順は[状態の所有と失敗時の復旧](design.md)を参照してください。
