# 0.7.4

DSH `0.2.1-alpha.2` と `0.2.1-alpha.3` の両方で起動できるようにし、自己更新の失敗でパッケージが消えたままになる経路を復帰させます。接続一覧の状態、モデルスイッチ、利用状況の再試行表示を、保存済みの事実に合わせます。

## 対応DSH

`@deepseek-ai/dsh-*` のpeerは `>=0.2.1-alpha.2 <0.3.0-0` です。`0.2.1-alpha.3` と `0.2.x` を受け、`0.3.0` とそのプレリリースは受けません。Cordisとschemasteryはこれまでのexactのままです。保存済み資格情報の解決は、DSH 0.2.1-alpha.3 では起動時の環境変数より先です。

## 自己更新

導入済みパッケージを上書きできない場合は、削除の完了を待ってから同じ操作で導入します。削除が失敗と返っても、一覧でパッケージが消えていれば、削除前の導入元とON/OFFを別の操作IDで入れ直します。削除後の導入が失敗し、パッケージが消えているときも同じです。ピンしていないGitHub導入元から別の版が入ったときは、その版を削除してから削除前の版をタグ付きで入れます。削除のあとに一覧を読めないときは、削除より前の記録では残っていると扱いません。入れ直しが例外で終わり一覧も読めないときは、手動導入の案内を出します。入れ直しまたはタグの導入が完了して一覧だけ失敗したときは、導入結果の版を見ます。タグの導入が完了したあとに一覧が失敗したときは、元の導入元へは戻しません。削除またはタグの導入が失敗したときは、元の導入元を入れ直します。版が一致しないときは、入っている版と直前の版が違うことを表示します。入れ直せた場合も、新しい配布版は失敗として表示します。入れ直しに失敗した場合は、直前の版を手動で導入する案内を出します。認証情報は更新処理では消しません。

すでに動いているより新しい版は「再起動は不要」と表示します。設定による無効化とは分けます。

## 画面

ボタン、入力、スイッチ、メニュー、モーダルはHostの `@deepseek-ai/dsh-client-ui-primitives` をそのまま使います。Escapeは手前のダイアログだけを閉じます。

接続一覧は、設定・資格情報・アダプターの変更通知とプロファイル切替を受けます。開いていない間は一覧を取りにいきません。開いている編集のrevisionは、通知で先に進めません。

モデルの再取得が、保存済みスイッチより古い一覧で表示を戻すことはありません。

保存しただけのAPIキーは「保存済み・未確認」です。接続確認が取れた行だけ緑の「接続済み」です。

利用状況の再取得に失敗したとき、数値が無い場合と、前回値を残している場合を分けて表示します。Retry-Afterの時刻を過ぎるか、タブが再表示されたら更新ボタンを押せます。自動では再取得しません。日付だけのリセット日は、その暦日のまま表示します。

## 確認
