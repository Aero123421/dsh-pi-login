# 0.7.2

Muse Codeのモデル重複と、上段の「Delete」を押しても接続が残る問題を修正しました。

## モデル一覧

- 提供元の `-contributor` 付き実IDと、プラグインが追加したContributor選択を1つにまとめます。Wonder Full、Wonder、Spark 1.3、Spark 1.2の通常版・Contributor版が両方返る場合は、12項目ではなく8選択肢になります。保存済みの一覧も追加取得なしで整理します。
- APIへは提供元が返した実ID・能力情報を使い、通常版は `x-tbh-contributor-mode: 0`、Contributor版は `1` を送ります。baseだけがContributorモードに返る形式にも対応し、提供元が返していないbaseモデルは作りません。
- Contributorは明示的な選択でだけオンにします。旧native Contributor行の既定オン状態は承認とみなしません。保存済みの明示的な選択は保持し、旧native行にオフ指定があればオフを優先します。新しいContributor選択をオンにしても、通常版のオフを解除しません。
- 旧 `-contributor` の重複項目をチャット側で選んでいた場合は、まとめられたContributor項目を選び直してください。

## 接続の設定と削除

- プラグインの接続を、DSH標準の上段プロバイダー編集欄へ登録するのをやめました。標準のDeleteは接続内のprofileだけをunsetする処理で、接続・認証を管理するこのプラグインの削除には不適合でした。
- 「AI connections」の各行に「Settings」（日本語では「設定」）を表示します。そこで「Delete connection」→確認を行うと、接続と専用のCredentialsを削除します。他の接続には影響させません。
- オフにしたモデルは再取得・再起動後もオフを保持します。接続削除後に取得が遅れて完了しても、接続・認証・モデルを復活させません。

旧版の上段Deleteでモデル設定がリセットされていた場合は、更新後にオン／オフを確認して選び直してください。消えた選択設定は、この更新で自動復元できません。

## 検証

単体テスト150件、公式Hostとの互換性、実Pi SDKとローカルHTTP応答による両形式のモデル一覧・実IDとヘッダー送信・旧オフ設定の保持・取得中削除を検証しています。

実DSH 0.2.1-alpha.2にテスト用の保存済み一覧とCredentialsを用意し、本物のSettings画面で、上段の重複編集欄がないこと、8選択肢、通常版とContributorのオフ操作、再起動後の保持、削除確認、実Credentials削除、再起動後の非復活、別接続の保持を確認しています。今後のCIとRelease workflowでもこの操作テストを必須にします。Chromiumの390/768/1440px・light/darkと配布チェックサムも検証します。

この検証はテスト用の応答・認証情報によるものです。実アカウントでのMuse生成・利用枠・課金、OS実機は未検証です。0.7.1の保存済み接続からの起動修正も維持します。
