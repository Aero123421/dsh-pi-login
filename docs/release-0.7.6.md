# 0.7.6

DSH `0.2.1-rc.2` に検証基準を更新し、PiからDSHへのストリーム変換、ChatGPTの新ログイン、Muse Codeのモデル管理を修正しました。更新後はDSHを再起動してください。保存済みの接続、認証情報、モデルのON/OFF、明示した上限設定は維持します。

- 壊れたツール引数を有効な空引数へ変換せず、`INVALID_TOOL_ARGUMENTS` として終了します。正常な `{}` は受け付けます。
- Pi 1.3.0の引数ストリームで、断片ごとの全体JSON再パースを除去しました。完成時の厳密な検証は保持し、修正済みSDKを配布物へ含めます。
- 一時的な上流ストリーム障害を、DSHが再試行できるエラーへ分類します。認証・不正リクエストは再試行対象へ広げません。
- 画像送信と `imageRequestTarget()` の寸法計算を揃え、画像予算を小さくしたCUAでも座標の縮尺を合わせます。
- Cordis・Schemasteryの安定版peerに対応します。明示した資格情報が欠ける接続はチャットの候補を非表示にし、編集用の一覧は保持します。
- 新しいOpenAI ChatGPTログインでは、アカウントが提供する表示対象モデルを取得します。再起動・期限切れ・再ログインで再取得し、未知のモデルは能力未確認・初期オフとします。
- `gpt-6.1-sol` はPiの既定値に従い、従来Codex OAuthは500K、新ChatGPTログインとAPIキーは272Kです。Fastも共通で、手動の上限設定を優先します。新ログインのUsageは未対応と表示し、従来Codex用APIへトークンを送りません。
- Muse Code 1.4.10までの変更履歴を照合しました。Standard／Contributor別のモデルID・effort・既定値・上限を保ち、`tier` 形式のeffortにも防御的に対応します。契約状態が欠ける場合は「不明」と表示します。
- モデル保存に失敗した場合、Hostの確定状態を再取得します。保存状態も確認できない場合は追加の切替を止め、「保存状態を確認」から復旧できます。

独立レビューで見つかったChatGPTの起動時・期限切れ後の再取得不足と、空カタログ時の手動上限設定の扱いは修正し、回帰テストを追加しています。

自動検証は固定DSHソース、実SDK、ローカル応答fixture、Chromium、隔離profileを使用します。実アカウントのOAuth、アカウント固有のMuse／SIWC能力・利用枠・課金、500K入力の実推論、ネイティブCUA操作は未検証です。
