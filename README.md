# DS Harness Pi接続・モデル管理

公式DeepSeek Harness用の独立PiアダプターとログインUIです。このリポジトリだけで開発・検証・配布できます。日本語言語パックのインストールは不要で、両方を一緒に使うこともできます。ログインUIの日本語辞書は含みますが、アプリ全体の日本語化とフォントは別の言語パックが担当します。

パッケージ名は`@local/dsh-pi-login`です。Pi SDKは`@earendil-works/pi-ai`の1.1.0を固定し、DS本体とは別に更新します。対象は公式`0.2.1-alpha.2`、コミット`d743267388641bc76f17c45ce8b4c231aed1d32c`です。検証する公式ソースを[upstream.json](upstream.json)に記録しています。

## ビルドとインストール

Node.js 22.19.0以上で実行します。

```sh
npm ci
npm run build
npm test
npm run pack:plugin
```

`artifacts/local-dsh-pi-login-0.2.0.tgz`と`artifacts/SHA256SUMS`ができます。公式アプリのプラグイン管理画面で配布ファイルを指定してインストールし、バンドルを有効にしてください。ファイルの場所はHarnessのHostから参照できる必要があります。

WebプロファイルではCLIでも追加できます。

```sh
dsh plugin --profile web add /absolute/path/local-dsh-pi-login-0.2.0.tgz
```

デスクトップのプロファイルにはアプリのプラグイン管理画面を使います。更新した場合はアプリを再起動してください。

## ログインとモデルの選択

設定のモデル画面に追加した操作欄から、プロバイダーと接続方法を選び、ログインします。ブラウザの認証、認証コード、APIキー入力など、そのプロバイダーが要求する操作を行います。認証完了後に「プロバイダーのモデルを有効にする」を押すとモデルを選べます。

公式のメニュー、スイッチ、入力欄、モーダルを再利用し、HostのReactと共有します。本体の標準フォームは独自の設定名前空間に未対応なので、接続・ON/OFFは追加した操作欄を使用します。

モデルをオフにすると一覧と実行対象から外れます。プロバイダーをオフにしても設定や認証情報は削除しません。新しいSDKのモデルは、既存の明示的なモデル一覧で絞り込んでいなければ標準で有効になります。既存モデルのOFF指定は維持します。

プロバイダーに`apiKeyEnv`が設定されている場合、そのAPIキー参照が保存済みのPi認証より優先されます。有効化の際に案内を表示し、「保存したログインを使う」を選ぶと参照を解除して保存済みの認証に切り替えます。

## 既存のDS設定との関係

構成パッチで組み込みのPiアダプターを停止し、プラグイン版だけを起動します。既存のプロバイダー設定は初回に`dsh-pi-login`へ取り込み、元の設定は保持します。認証情報は既存の`llm-pi-ai/<provider>`を使います。アンインストールして再起動すると組み込みアダプターに戻り、元のモデル設定が再び使われます。プラグイン側で変更したON/OFFは組み込みアダプターには適用されません。

トークン更新はプラグイン版のSDK、保存先は公式のCredentialsサービスが管理します。認証情報はブラウザのlocalStorage、ログ、共有イベントへ保存しません。認証URL・コード・入力待ちは操作を開始した画面専用の一時チケットで扱い、キャンセルやアンインストールで終了します。認証処理は公式のAuthorization APIと認証済みConnectionを使います。

OpenAI OAuth用のインストールIDは、`dsh-pi-login/installation`という別のCredentialsレコードに保存します。システムプロンプト、エージェント処理、元の会話変換・推論設定・ツール履歴・画像処理・ストリーム処理は維持しています。アダプターの由来と変更点は[src/runtime/UPSTREAM.md](src/runtime/UPSTREAM.md)を参照してください。

## 検証

ビルド後に実行します。

```sh
npm run test:compat
npm run test:runtime
npx playwright install chromium
npm run test:browser
```

初回のビルドでは固定した公式ソースを`.cache/upstream`へ取得します。互換性チェックは公式のCordis、Authorization、Credentials、Connectionを使い、認証情報の保存と解除を確認します。runtime検証では実際のPi SDKを使い、全チャットプロバイダーのモデル解決、APIキー保存、ローカルのテスト用サーバーへの生成リクエスト、設定の取り込み、モデル・プロバイダーのON/OFFを確認します。設定の永続化とLLMの登録先には検証用のサービスを使います。

ブラウザ検証はこのプラグインだけを読み込み、公式のスロット・言語・認証APIでログイン入力、キャンセル、認証していないリクエストの拒否、モデル・プロバイダーの選択、明暗テーマ、狭い画面、アンロードを確認します。フィクスチャ内で日本語を登録しますが、日本語プラグインやフォントは使いません。スクリーンショットは`artifacts`に出力します。

GitHub Actionsには、依存関係・ビルド・単体テスト・互換性・runtime・ブラウザ検証・パッケージ作成のチェックを設定しています。実アカウントのOAuth、実プロバイダーへの生成リクエスト、公式デスクトップへのインストール、Windows・macOS実機は未検証です。

## Pi SDKと上流の更新

```sh
npm run update:pi
# または検証するSDKを指定
npm run update:pi -- 1.1.0
```

SDKを固定版へ更新し、このプラグインのパッチ版を上げます。DependabotにもSDKの更新を毎週確認する設定を入れています。更新後はビルド・検証・パッケージ作成を行い、更新したプラグインを配布します。ログインし直すだけで未知のモデルが追加される仕組みではありません。実行中にnpmから未検証のコードを取得して切り替えません。

DSの公式版へ追従する場合は`upstream.json`のコミット・バージョンを変更して古い`.cache/upstream`を退避し、`src/runtime`を元アダプターと比較します。HostのpeerDependencies、公式UI部品、認証・LLM APIの互換性を確認して検証してください。
