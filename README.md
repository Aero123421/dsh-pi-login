# DS Harness Piログイン

Pi対応プロバイダーのログインとモデル選択をDeepSeek Harnessに追加します。Pi SDKはプラグイン側で更新します。

対応版：DS Harness `0.2.1-alpha.2`。SDK：`@earendil-works/pi-ai` `1.1.0`。

## 導入

サイドバーの「Plugins → Add plugin」を開き、次を入力します。

```text
github:Aero123421/dsh-pi-login
```

「Install」→「Enable now」を押し、アプリを再起動します。ビルド済みのファイルを含むため、インストール時のビルドは不要です。特定の版を使う場合は[配布ファイルとチェックサム](https://github.com/Aero123421/dsh-pi-login/releases/tag/v0.5.0)を使えます。

WebプロファイルではCLIからも追加できます。

```sh
dsh plugin --profile web add -w github:Aero123421/dsh-pi-login
```

## 使い方

「設定 → モデル」のPi接続欄で、プロバイダーとログイン方法を選びます。認証を終えたら「プロバイダーを有効にする」を押し、「モデルを選ぶ」で使うモデルをオンにします。

プロバイダーが有効なとき、オンにしたモデルをチャットやエージェントで使えます。モデルをオフにすると一覧と実行対象から外れます。プロバイダーをオフにしても認証情報とモデルの選択は残ります。

`apiKeyEnv`で指定したAPIキーはログイン認証より優先されます。切り替えるには、認証後に表示される「保存済みの認証を使う」を選びます。

## Fast

対応モデルは、通常版とFast版を別々に選べます。例：`GPT-6.1 Sol`、`GPT-6.1 Sol Fast`。Fast版は最初はオフです。「モデルを選ぶ」でオンにすると、チャットやエージェントのモデル一覧に追加されます。通常版をオフにしてFast版だけを使うこともできます。

認証情報とモデルの能力は共通です。Thinking effortは両方で選べます。Fast版を選んだ呼び出しにFastを指定し、通常版には標準処理を指定します。

Fastは通常より高いAPI料金・ChatGPTクレジット消費が発生します。利用可否はモデルと契約によります。Fastが拒否された場合はエラーを表示するので、通常版を選び直してください。接続先が標準処理に振り分ける場合もあります。[OpenAI Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)

対応モデルと実装は[Fastの開発資料](docs/fast.md)を参照してください。

## 既存の設定

組み込みのPiアダプターを停止し、このプラグインのアダプターを使います。初回起動で既存の設定をコピーし、保存済みの認証情報を引き継ぎます。システムプロンプトは変更しません。

アンインストールして再起動すると組み込みアダプターに戻ります。元の設定が使われるため、このプラグインで変更したON/OFFは反映されません。

## プラグインの更新

「設定 → モデル」のPi共通欄に実行版と「プラグインの更新を確認」を表示します。更新確認と導入は別操作です。候補と変更内容を確認し、「プラグインを更新する」を押してください。導入後に再起動が必要な場合は、現在の作業を終えてからDSHを再起動してください。モデル一覧の更新とは別の処理です。

GitHubから導入した場合は正式Releaseのタグへ更新します。配布tgzから導入した場合は、固定した配布元のチェックサム・package名・版・DSH互換性を検証してから、profile内のtgzへ更新します。既存の版固定を最新追従へ変更せず、bundleのON/OFF、認証情報、モデルとFastの選択を維持します。ログインや設定保存の途中には更新できません。

managerがない、profileが読み取り専用、導入元が開発用ディレクトリや独自ファイルの場合は、理由と手動更新先を表示します。GitHub APIの取得失敗や互換性不明を「最新版」と扱いません。切断時は操作IDで照合し、結果不明のまま導入を再送しません。配布物の検証ファイルと機密情報を含まない操作記録はprofileの`.dsh-pi-login-updates/`へ保存します。profileが参照するtgzを消さないでください。

## 更新と検証

Muse Wonder（`muse-wonder-1.0`）に対応しています。Metaの既存の接続方法で使えます。「モデルを選ぶ」で確認してください。SDK未収録のため、プラグイン側でモデル情報を補完しています。[モデル情報と根拠](docs/models.md)

MetaでMuseログインを使っている場合は、「モデルを選ぶ → モデル一覧を更新」で契約情報とアカウントの最新モデル一覧を取得できます。契約が有効で、一覧にWonder FullやContributorのIDが返れば、選択候補に追加します。新しく取得したモデルは最初はオフです。能力情報が返らないモデルは、テキスト・接続先の既定の推論・設定したトークン上限で扱い、その旨を表示します。

実アカウントでのFullの生成・Contributor利用枠は未検証です。一覧にないモデルのIDや権限は推測しません。明示したモデル一覧や以前のON/OFFは保持します。取得した一覧は実行中だけ保持するため、再起動・Metaへの再ログイン後には再読み込みが必要です。APIキー参照が優先されている場合は「保存済みの認証を使う」に切り替えてください。更新の画面とAPIはプロバイダー共通です。現在、実APIからの再取得に対応するのはMetaのMuseログインです。他のプロバイダーは未対応の案内を表示し、SDKまたはプラグインの更新でモデルが追加されます。

テストには公式ソース、Pi SDK、モック認証、ローカルの生成サーバーを使っています。実アカウントのOAuth、実プロバイダーへの生成リクエスト、公式デスクトップへのインストール、Windows・macOS実機は未検証です。
