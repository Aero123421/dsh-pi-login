# DS Harness Piログイン

Pi対応プロバイダーのログイン、接続ごとのモデル選択、アカウントの利用状況をDeepSeek Harnessに追加します。同じサービスで個人用OAuth、会社用APIキー、別Gatewayを個別に管理できます。モデル一覧はSDKと独立して更新し、通信・認証の実装に変更が必要な場合はプラグインを更新します。

対応範囲：DS Harness `0.2.1-alpha.2` 以上、`0.3.0` 未満（`0.3.0` のプレリリースは含まない）。基本受入対象：npm latestの`0.2.1-rc.2`。追加検証：nextの`0.2.1-rc.5`とalphaの`0.2.2-alpha.2`（版確認の締切は2026-10-29 15:00 UTC）。SDK：`@earendil-works/pi-ai` `1.4.0`。[対象版・モデルと認証の確認範囲](docs/compatibility-2026-10.md)

日本語の表示には [dsh-japanese](https://github.com/Aero123421/dsh-japanese) が必要です。このプラグインは日本語の文面を登録するだけで、言語そのものは追加しません。dsh-japanese を導入して言語を日本語にすると、接続画面の文面が日本語になります。未導入のときは英語で表示し、中国語を選んだときも英語の文面に戻します。

## 導入

サイドバーの「Plugins → Add plugin」を開き、次を入力します。

```text
github:Aero123421/dsh-pi-login
```

「Install」→「Enable now」を押し、アプリを再起動します。ビルド済みのファイルを含むため、インストール時のビルドは不要です。ビルドで Pi SDK 1.4.0 を dist に同梱するため、実行時の依存は不要です。導入時に `@google/genai` と `protobufjs` は入らず、それらの build script も走りません。特定の版を使う場合は[配布ファイルとチェックサム](https://github.com/Aero123421/dsh-pi-login/releases/tag/v0.8.0)を使えます。

WebプロファイルではCLIからも追加できます。

```sh
dsh plugin --profile web add -w github:Aero123421/dsh-pi-login
```

## 使い方

「設定 → モデル」の「AI接続」で「接続を追加」を押し、サービスと認証方法を選びます。接続名は空欄ならサービス名になります。OAuthは「追加してログイン」でそのままログインし、成功すると接続がオンになります。APIキーは入力して「追加」を押すとオンで作成します。続けて「モデルを選ぶ」で使うモデルをオンにしてください。

一覧はサービスごとに接続を並べ、各行に接続名・認証方法・状態を表示します。行のスイッチで接続をオン/オフし、「モデル」でモデルを選びます。未ログインや認証切れの行には「ログイン」「再ログイン」を表示します。接続名を押すと、その接続の状態・利用状況・設定・複製・削除をまとめた画面を開きます。接続が9件以上あると検索欄を表示します。同じモデルでも接続が違えば独立した選択肢になり、接続名でアカウントを区別できます。

接続がオンのとき、オンにしたモデルをチャットやエージェントで使えます。接続をオフにしても認証情報とモデルの選択は残り、オフのままでもモデルを選べます。「設定を複製」はモデル設定だけを複製し、新しい接続は未認証・オフで作成します。認証方式の変更や削除は接続の画面で確認して実行します。

各呼び出しは選択した接続の認証・URLを使います。認証切れ、利用枠超過、削除時に別アカウントや標準モデルへ自動で切り替えません。独自URLにはHost設定の`trustedEndpointOrigins`に、そのURLのorigin（例：`https://gateway.example`）を明示しておく必要があります。画面から信頼先は追加できません。URLへのAPIキー埋め込みはできず、秘密ヘッダーはHostのCredentials参照で指定します。

新しいGateway接続は、モデル能力を明示しない場合にテキスト・接続先既定の推論で扱い、未確認と表示します。画像やThinkingが必要な場合はHost側のモデル宣言で設定してください。

旧設定の`apiKeyEnv`は移行後も優先されます。同じ旧設定に保存済みOAuthもある場合は、元のrouteを持つAPI参照接続と、オフで作成する保存済みOAuth接続の2件へ分けます。OAuth接続を有効にすれば再ログインせず使用でき、API側の鍵変更・削除でOAuthを失いません。

## サービス別の画面とモデル自動更新

接続画面を「Pi」「Meta」「CommandCode」「Ollama Cloud」「OpenCode」に分けています。GoとZenはOpenCode内で個別の接続として管理します。既存の接続・モデル選択・認証情報は引き継ぎます。

標準接続のモデル一覧は、初回参照時と約1時間ごとに自動取得し、「モデル一覧を更新」でも再取得できます。成功した一覧はプロファイルの`.dsh-pi-login/catalog-<接続ID>.json`へ保存し、再起動後に復元します。0.8.0の設定内`modelCatalog`は初回起動でこのファイルへ移し、設定から削除します。新しいモデルは初期オフです。明示したモデル一覧や独自Gatewayの設定は上書きしません。Pi公開カタログへの掲載待ちや、未対応の通信方式があるため、すべての新モデルが即時に利用可能になる保証はありません。[取得元・Effort・互換性の詳細](docs/live-catalogs.md)

CommandCodeとOllama Cloudは、それぞれの画面からAPIキーで追加します。CommandCodeは公開モデル一覧と対応エンドポイントを読み、Ollama Cloudはその接続のキーで`/api/tags`と`/api/show`を読みます。Ollamaの版付きモデルIDは取得した値をそのまま使います。Effortは確認できた値だけを表示し、取得できない場合はサービス既定を使います。

CommandCodeのProvider APIは利用プランの条件があります。CLI向けの契約と外部APIの利用権限は同一ではないため、[CommandCodeの案内](https://commandcode.ai/)で確認してください。モデル一覧への掲載だけでは、そのキーでの生成可否を保証しません。

Ollama Cloudは残高API、CommandCodeは内部のcredits APIから取得できた利用枠を表示します。APIの仕様や権限で取得できない場合はエラーを表示し、生成とは独立して扱います。

## ChatGPTの接続とコンテキスト

モデル一覧の更新方法は[自動更新の仕様](docs/live-catalogs.md)も参照してください。以下のPi 1.4.0の上限は同梱カタログの値で、公開カタログから取得できた場合はその値で更新します。ChatGPTログインはアカウント専用の取得処理を使います。

従来の「OpenAI Codex」と、新しい「OpenAI → Sign in with ChatGPT」は別の接続です。新ログインではログインしたアカウントのモデル一覧を取得し、表示対象のモデルだけを順序どおりに選べます。アカウント変更・再ログインで一覧を更新します。未取得・取得失敗では静的カタログを契約上使えるモデルとして表示しません。「モデル一覧を更新」で再取得できます。

Pi 1.4.0の `gpt-6.1-sol` は従来Codex OAuthが500,000、新ログインとAPIキーが272,000トークンです。Fastも同じ上限です。手動の `modelOverrides` は優先され、古い272Kの指定を自動で500Kへ変更しません。新ログインのモデル一覧はコンテキスト上限を保証しないため、500Kを一律に付けません。未知のモデルは能力未確認・初期オフで追加します。

新ログインの推論は公開Responses APIへ送信し、従来Codex専用の接続先や利用枠APIは使いません。新ログインのアカウント利用枠は未対応と表示します。[モデル仕様と検証範囲](docs/models.md)

## OpenCode Zen と Go

OpenCode の API キーで、Zen（従量）と Go（月額）に接続できます。どちらも OAuth はありません。

設定画面では「OpenCode」にまとめています。標準接続の一覧はPiの公開カタログから自動更新し、Goのセッションヘッダーなどの通信処理はPi SDKを使います。以下のURLは同梱カタログの値です。

1. [OpenCode Zen](https://opencode.ai/docs/zen/) では Console にサインインし、支払い情報とクレジットを追加して API キーをコピーします。[OpenCode Go](https://opencode.ai/docs/go/) では Go または Go Plus を契約してから API キーをコピーします。
2. 「設定 → モデル」の「接続を追加」でサービス「OpenCode Zen」または「OpenCode Go」を選び、API キーを入力して「追加」します。
3. 「モデル」で使うモデルをオンにします。接続先を空のままにすると、SDK のモデル定義を使います。Zen の `deepseek-v4.1-flash-free` は `https://opencode.ai/inference/v1` へ、パス `/chat/completions` を付けて送ります。Go の OpenAI 互換モデルは `https://opencode.ai/inference/go/v1`、Anthropic 形式のモデルは `https://opencode.ai/inference/go` です。同じ日の Zen 文書は `https://opencode.ai/inference/openai/v1/chat/completions` も案内しています。空の接続先では SDK の URL を使います。

Go は会話ごとの `x-opencode-session` を要求します。Harness が session ID を渡した呼び出しでは、Pi SDK がそのヘッダーを付けます。2026-10-16 に、このヘッダーがない Go の `deepseek-v4.1-flash` は 400 `MissingSessionID`、ヘッダーだけでキーがない場合は 401、無効なキーは 401 `Invalid credential` でした。

2026-10-16 に、キーなしの `deepseek-v4.1-flash-free` を SDK の URL と文書の URL の両方へ送ると、どちらも 403 `FreeTierError` でした。Authorization を付けた OpenCode 以外のクライアントも同じ 403 で、応答は無料枠が OpenCode 内からだけ使えるというものでした。有効な API キーでの生成は未検証です。

Zen の無料モデルは期間限定です。提供元によっては、その期間の利用データをモデルの改善や学習に使います。OpenCode の説明では、Big Pickle、LL Alpha Free、Exo Free、MiMo の無料モデル、Nemotron の無料エンドポイント、Muse Spark 1.3 Contributor Free がこの対象です。DeepSeek V4.1 Flash Free、GLM-5.3-Flash Free、Space Bunny Free、LongCat 2.5 Preview Free は、学習に使わず保持しないとされています。条件は変わるので、使う前に [Zen の料金とプライバシー](https://opencode.ai/docs/zen/) を確認してください。

Go の `deepseek-v4.1-flash` は無料モデルではありません。契約の利用枠を使う有料モデルで、Zen の `deepseek-v4.1-flash-free` とは別の ID です。Go の一覧に `deepseek-v4.1-flash-free` はありません。

Go の API キー接続は、利用枠を `https://opencode.ai/inference/go/v1/usage` から読みます。接続先が空でも、`https://opencode.ai/inference/go`、`https://opencode.ai/inference/go/v1`、以前の `https://opencode.ai/zen/go` でも同じ取得先です。2026-10-16 に、この URL と以前の `https://opencode.ai/zen/go/v1/usage` はキーなしでどちらも 401 `AuthError` でした。成功した利用枠の応答は未検証です。Zen の利用枠取得はこのプラグインでは未対応です。

## アカウントの利用状況

接続名を押して開く画面に、そのアカウントの利用枠を表示します。モデル生成時のトークン数・推定料金とは別の情報です。取得対応はサービスと認証方法によります。取得できない接続は未対応と表示し、使用量0とは扱いません。

応答に含まれる期間・使用率・残量・リセット時刻だけを表示します。取得時刻と提供元での観測時刻を分け、認証切れ、回数制限、古い情報、無制限、不明を区別します。前回値が残っていても最新値とは表示しません。接続の画面を開いたときや「利用状況を更新」を押したときに読み取り、更新連打や同時タブの取得はHost側でまとめます。内部HTTP APIを使うため、提供元の仕様変更で取得できなくなる場合があります。

## Fast

対応モデルは、通常版とFast版を別々に選べます。例：`GPT-6.1 Sol`、`GPT-6.1 Sol Fast`。Fast版は最初はオフです。行の「モデル」でオンにすると、チャットやエージェントのモデル一覧に追加されます。通常版をオフにしてFast版だけを使うこともできます。

認証情報とモデルの能力は共通です。Thinking effortは両方で選べます。Fast版を選んだ呼び出しにFastを指定し、通常版には標準処理を指定します。

Fastは通常より高いAPI料金・ChatGPTクレジット消費が発生します。利用可否はモデルと契約によります。Fastが拒否された場合はエラーを表示するので、通常版を選び直してください。接続先が標準処理に振り分ける場合もあります。[OpenAI Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)

対応モデルと実装は[Fastの開発資料](docs/fast.md)を参照してください。

## 既存の設定

組み込みのPiアダプターを停止し、このプラグインのアダプターを使います。初回起動でプロファイルごとに一度だけ旧設定を接続へ変換します。既存のモデル・Fast・Thinking設定と履歴のrouteを保持し、保存済み認証は元のCredentialsレコードを参照します。認証情報を複製せず、通常の保存済みOAuth・APIキーでは再ログイン不要です。

移行は接続と完了記録を1回の設定更新で保存します。失敗時には旧設定と認証を残し、再起動で再試行します。旧設定に直接記載したヘッダー、未対応の独自route、設定の書き込み不可がある場合は修復が必要です。移行前にプロファイルの設定とCredentialsをバックアップし、失敗時は旧版を維持してください。直接記載したヘッダーはCredentialsへ移して参照に置き換え、独自routeは対応サービスの接続として再設定します。詳細は[移行の制約と回復手順](docs/development.md#接続移行と回復)を参照してください。

アンインストールして再起動すると組み込みアダプターに戻ります。元の設定が使われるため、このプラグインで変更したON/OFFは反映されません。DSH 0.2.1-rc.2はプラグインへ解除専用の後始末を渡さないため、モデル一覧のキャッシュはプロファイルの`.dsh-pi-login/`に残ります。カタログファイルはこのディレクトリだけです。不要ならディレクトリごと削除してください。

## プラグインの更新

「AI接続」の下に実行版と「プラグインの更新を確認」を表示します。更新確認と導入は別操作です。候補と変更内容を確認し、「プラグインを更新する」を押してください。導入後に再起動が必要な場合は、現在の作業を終えてからDSHを再起動してください。モデル一覧の更新とは別の処理です。

GitHubから導入した場合は正式Releaseのタグへ更新します。配布tgzから導入した場合は、固定した配布元のチェックサム・package名・版・DSH互換性を検証してから、profile内のtgzへ更新します。既存の版固定を最新追従へ変更せず、bundleのON/OFF、認証情報、モデルとFastの選択を維持します。ログインや設定保存の途中には更新できません。

managerがない、profileが読み取り専用、導入元が開発用ディレクトリや独自ファイルの場合は、理由と手動更新先を表示します。GitHub APIの取得失敗や互換性不明を「最新版」と扱いません。切断時は操作IDで照合し、結果不明のまま導入を再送しません。配布物の検証ファイルと機密情報を含まない操作記録はprofileの`.dsh-pi-login-updates/`へ保存します。profileが参照するtgzを消さないでください。

導入済みパッケージを置き換えるDSHでは、いったん削除してから新しい配布版を導入します。その導入が失敗してパッケージが無くなっている場合は、削除前の導入元とON/OFFを別の操作IDで入れ直します。入れ直しできた場合は失敗として表示し、認証情報は残します。入れ直しも失敗した場合は、直前の配布版を手動で導入する案内を出します。削除に失敗した場合は、もう一度導入しません。

## Meta Muse Code

MetaのMuse Code契約は、接続追加でサービス「Muse Code」を選び、「追加してログイン」でMetaアカウントを承認すると使えます。公式`muse` CLIは不要です。ログイン（端末コード）とAPIキーの発行・自動更新は公式CLIと同じ方式で、Pi SDKのMetaプロバイダーが行います。

行の「設定」で接続の編集・複製・削除を行います。削除は接続と専用の認証情報を対象とし、確認後に実行します。接続は上段の標準プロバイダー編集欄には重複表示しません。

行の「モデル」を開くと、そのアカウントのMuse Code用モデル一覧（`/muse-code/models`）を読み込みます。Wonder、Wonder Fullなど一覧にあるモデルと、それぞれ1つのContributor版を個別のスイッチでオンにでき、オンにしたモデルはチャットやエージェントのモデル選択に出ます。Contributor版は、Metaが内容を学習に使う代わりに利用枠が増えるモードで、最初はオフです。提供元の`-contributor`付きIDとプラグインのContributor選択を1つにまとめ、APIへは提供元が返した実モデルIDと`x-tbh-contributor-mode`を送ります。同じIDのContributorは、そのモードの一覧にある推論レベルと出力上限を使い、StandardのMaxを引き継ぎません。読み込んだ一覧は接続に保存するので、再起動後も使えます。利用状況は契約の利用枠を表示します。

一覧の項目名とContributorヘッダーは公式CLI 1.4.7の実装を基準に、1.4.10までの変更履歴と照合しています。推論レベル・既定値・コンテキスト・出力上限は、StandardとContributorそれぞれのアカウント一覧を使います。契約状態の欠落は「不明」と表示します。実アカウントでの生成・Contributor利用枠・課金は未検証です。0.6.xの（CLI経由の）Muse Code接続は再ログインが必要です。[モデル選択の詳細](docs/models.md#meta-muse-code)

## Meta Model API（Pi経由）のMuseモデル

Muse Wonder（`muse-wonder-1.0`）に対応しています。Metaの既存の接続方法で使えます。行の「モデル」で確認してください。Pi SDK 1.4.0 のカタログにこのモデルがあるため、その定義を使います。SDKに同じIDが無い場合だけ、プラグイン側の補完を使います。[モデル情報と根拠](docs/models.md)

MetaでMuseログインを使っている場合は、行の「モデル」→「モデル一覧を更新」で契約情報とアカウントの最新モデル一覧を取得できます。契約が有効で、一覧にWonder FullやContributorのIDが返れば、選択候補に追加します。新しく取得したモデルは最初はオフです。能力情報が返らないモデルは、テキスト・接続先の既定の推論・設定したトークン上限で扱い、その旨を表示します。

実アカウントでのFullの生成・Contributor利用枠は未検証です。一覧にないモデルのIDや権限は推測しません。明示したモデル一覧や以前のON/OFFは保持します。取得した一覧は実行中だけ保持するため、再起動・Metaへの再ログイン後には再読み込みが必要です。APIキー参照が優先されている場合は「保存済みの認証を使う」に切り替えてください。更新の画面とAPIはプロバイダー共通です。MetaのMuseログインと標準接続先のOpenAI ChatGPTログインは既存のアカウント専用取得を使います。Pi標準接続・OpenCode Go／ZenはPiの公開カタログ、CommandCode・Ollama Cloudは各サービスの一覧からモデル情報を更新します。独自URLや明示的なモデル一覧がある接続は自動更新の対象外です。[取得元と更新条件](docs/live-catalogs.md)

テストには公式ソース、Pi SDK、モック認証、ローカルの生成サーバーを使っています。実アカウントのOAuth、実プロバイダーへの生成リクエスト、公式デスクトップへのインストール、Windows・macOS実機は未検証です。
