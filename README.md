# DS Harness Piログイン

Pi対応プロバイダーのログイン、接続ごとのモデル選択、アカウントの利用状況をDeepSeek Harnessに追加します。同じサービスで個人用OAuth、会社用APIキー、別Gatewayを個別に管理できます。Pi SDKはプラグイン側で更新します。

対応版：DS Harness `0.2.1-alpha.2`。SDK：`@earendil-works/pi-ai` `1.1.0`。

## 導入

サイドバーの「Plugins → Add plugin」を開き、次を入力します。

```text
github:Aero123421/dsh-pi-login
```

「Install」→「Enable now」を押し、アプリを再起動します。ビルド済みのファイルを含むため、インストール時のビルドは不要です。特定の版を使う場合は[配布ファイルとチェックサム](https://github.com/Aero123421/dsh-pi-login/releases/tag/v0.7.0)を使えます。

WebプロファイルではCLIからも追加できます。

```sh
dsh plugin --profile web add -w github:Aero123421/dsh-pi-login
```

## 使い方

「設定 → モデル」の「AI接続」で「接続を追加」を押し、サービスと認証方法を選びます。接続名は空欄ならサービス名になります。OAuthは「追加してログイン」でそのままログインし、成功すると接続がオンになります。APIキーは入力して「追加」を押すとオンで作成します。続けて「モデルを選ぶ」で使うモデルをオンにしてください。

一覧はサービスごとに接続を並べ、各行に接続名・認証方法・状態を表示します。行のスイッチで接続をオン/オフし、「モデル」でモデルを選びます。未ログインや認証切れの行には「ログイン」「再ログイン」を表示します。接続名を押すと、その接続の状態・利用状況・設定・複製・削除をまとめた画面を開きます。接続が9件以上あると検索欄を表示します。同じモデルでも接続が違えば独立した選択肢になり、接続名でアカウントを区別できます。

接続がオンのとき、オンにしたモデルをチャットやエージェントで使えます。接続をオフにしても認証情報とモデルの選択は残り、オフのままでもモデルを選べます。「設定を複製」はモデル設定だけを複製し、新しい接続は未認証・オフで作成します。認証方式の変更や削除は接続の画面で確認して実行します。

各呼び出しは選択した接続の認証・URLを使います。認証切れ、利用枠超過、削除時に別アカウントや標準モデルへ自動で切り替えません。独自URLにはHost設定の`trustedEndpointOrigins`に、そのURLのorigin（例：`https://gateway.example`）を明示しておく必要があります。画面から信頼先は追加できません。URLへのAPIキー埋め込みはできず、秘密ヘッダーはHostのCredentials参照で指定します。

新しいGateway接続は、モデル能力を明示しない場合にテキスト・接続先既定の推論で扱い、未確認と表示します。画像やThinkingが必要な場合はHost側のモデル宣言で設定してください。

旧設定の`apiKeyEnv`は移行後も優先されます。同じ旧設定に保存済みOAuthもある場合は、元のrouteを持つAPI参照接続と、オフで作成する保存済みOAuth接続の2件へ分けます。OAuth接続を有効にすれば再ログインせず使用でき、API側の鍵変更・削除でOAuthを失いません。

## アカウントの利用状況

接続名を押して開く画面に、そのアカウントの利用枠を表示します。モデル生成時のトークン数・推定料金とは別の情報です。取得対応はサービスと認証方法によります。取得できない接続は未対応と表示し、使用量0とは扱いません。

応答に含まれる期間・使用率・残量・リセット時刻だけを表示します。取得時刻と提供元での観測時刻を分け、認証切れ、回数制限、古い情報、無制限、不明を区別します。前回値が残っていても最新値とは表示しません。接続の画面を開いたときや「利用状況を更新」を押したときに読み取り、更新連打や同時タブの取得はHost側でまとめます。内部HTTP APIを使うため、提供元の仕様変更で取得できなくなる場合があります。

## Fast

対応モデルは、通常版とFast版を別々に選べます。例：`GPT-6.1 Sol`、`GPT-6.1 Sol Fast`。Fast版は最初はオフです。行の「モデル」でオンにすると、チャットやエージェントのモデル一覧に追加されます。通常版をオフにしてFast版だけを使うこともできます。

認証情報とモデルの能力は共通です。Thinking effortは両方で選べます。Fast版を選んだ呼び出しにFastを指定し、通常版には標準処理を指定します。

Fastは通常より高いAPI料金・ChatGPTクレジット消費が発生します。利用可否はモデルと契約によります。Fastが拒否された場合はエラーを表示するので、通常版を選び直してください。接続先が標準処理に振り分ける場合もあります。[OpenAI Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)

対応モデルと実装は[Fastの開発資料](docs/fast.md)を参照してください。

## 既存の設定

組み込みのPiアダプターを停止し、このプラグインのアダプターを使います。初回起動でプロファイルごとに一度だけ旧設定を接続へ変換します。既存のモデル・Fast・Thinking設定と履歴のrouteを保持し、保存済み認証は元のCredentialsレコードを参照します。認証情報を複製せず、通常の保存済みOAuth・APIキーでは再ログイン不要です。

移行は接続と完了記録を1回の設定更新で保存します。失敗時には旧設定と認証を残し、再起動で再試行します。旧設定に直接記載したヘッダー、未対応の独自route、設定の書き込み不可がある場合は修復が必要です。移行前にプロファイルの設定とCredentialsをバックアップし、失敗時は旧版を維持してください。直接記載したヘッダーはCredentialsへ移して参照に置き換え、独自routeは対応サービスの接続として再設定します。詳細は[移行の制約と回復手順](docs/development.md#接続移行と回復)を参照してください。

アンインストールして再起動すると組み込みアダプターに戻ります。元の設定が使われるため、このプラグインで変更したON/OFFは反映されません。

## プラグインの更新

「AI接続」の下に実行版と「プラグインの更新を確認」を表示します。更新確認と導入は別操作です。候補と変更内容を確認し、「プラグインを更新する」を押してください。導入後に再起動が必要な場合は、現在の作業を終えてからDSHを再起動してください。モデル一覧の更新とは別の処理です。

GitHubから導入した場合は正式Releaseのタグへ更新します。配布tgzから導入した場合は、固定した配布元のチェックサム・package名・版・DSH互換性を検証してから、profile内のtgzへ更新します。既存の版固定を最新追従へ変更せず、bundleのON/OFF、認証情報、モデルとFastの選択を維持します。ログインや設定保存の途中には更新できません。

managerがない、profileが読み取り専用、導入元が開発用ディレクトリや独自ファイルの場合は、理由と手動更新先を表示します。GitHub APIの取得失敗や互換性不明を「最新版」と扱いません。切断時は操作IDで照合し、結果不明のまま導入を再送しません。配布物の検証ファイルと機密情報を含まない操作記録はprofileの`.dsh-pi-login-updates/`へ保存します。profileが参照するtgzを消さないでください。

## Meta Muse Code

MetaのMuse Code契約は、接続追加でサービス「Muse Code」を選び、「追加してログイン」でMetaアカウントを承認すると使えます。公式`muse` CLIは不要です。ログイン（端末コード）とAPIキーの発行・自動更新は公式CLIと同じ方式で、Pi SDKのMetaプロバイダーが行います。

行の「モデル」を開くと、そのアカウントのMuse Code用モデル一覧（`/muse-code/models`）を読み込みます。Wonder、Wonder Fullなど一覧にあるモデルと、それぞれのContributor版を個別のスイッチでオンにでき、オンにしたモデルはチャットやエージェントのモデル選択に出ます。Contributor版は、Metaが内容を学習に使う代わりに利用枠が増えるモードで、最初はオフです。選んだモデルに合わせて、リクエストごとに`x-tbh-contributor-mode`を送ります。読み込んだ一覧は接続に保存するので、再起動後も使えます。利用状況は契約の利用枠を表示します。

一覧の項目名とContributorヘッダーの値は、公式CLI 1.4.7の実装から読み取ったもので、実アカウントでの生成・Contributor利用枠・課金は未検証です。0.6.xの（CLI経由の）Muse Code接続は再ログインが必要です。[モデル選択の詳細](docs/models.md#meta-muse-code)

## Meta Model API（Pi経由）のMuseモデル

Muse Wonder（`muse-wonder-1.0`）に対応しています。Metaの既存の接続方法で使えます。行の「モデル」で確認してください。SDK未収録のため、プラグイン側でモデル情報を補完しています。[モデル情報と根拠](docs/models.md)

MetaでMuseログインを使っている場合は、行の「モデル」→「モデル一覧を更新」で契約情報とアカウントの最新モデル一覧を取得できます。契約が有効で、一覧にWonder FullやContributorのIDが返れば、選択候補に追加します。新しく取得したモデルは最初はオフです。能力情報が返らないモデルは、テキスト・接続先の既定の推論・設定したトークン上限で扱い、その旨を表示します。

実アカウントでのFullの生成・Contributor利用枠は未検証です。一覧にないモデルのIDや権限は推測しません。明示したモデル一覧や以前のON/OFFは保持します。取得した一覧は実行中だけ保持するため、再起動・Metaへの再ログイン後には再読み込みが必要です。APIキー参照が優先されている場合は「保存済みの認証を使う」に切り替えてください。更新の画面とAPIはプロバイダー共通です。現在、実APIからの再取得に対応するのはMetaのMuseログインです。他のプロバイダーは未対応の案内を表示し、SDKまたはプラグインの更新でモデルが追加されます。

テストには公式ソース、Pi SDK、モック認証、ローカルの生成サーバーを使っています。実アカウントのOAuth、実プロバイダーへの生成リクエスト、公式デスクトップへのインストール、Windows・macOS実機は未検証です。
